# 部署指南

## 一、本地预览（必须用本地服务器）

```powershell
uv run python -m http.server 8080
# 打开 http://localhost:8080/
```

> 直接双击 `index.html` 会因浏览器 CORS 限制读不到 `data/*.json`，页面会提示"数据加载失败"。
> `tools/record_demo.py` 默认从 **8123** 端口取页面，录屏时用 `--bind 127.0.0.1` 起在 8123。

## 二、配置百度地图 AK

1. 到 <https://lbsyun.baidu.com/apiconsole/key> 创建 **浏览器端** AK；
2. 「应用设置」里把 **Referer 白名单**填上：
   - 本地调试：`localhost`、`127.0.0.1`
   - 线上：`kint23.github.io`（或你的域名）
3. 把 AK 填进 `app/config.js` 的 `ak` 字段。

### `ak` 留空也没关系

页面会**自动切到离线示意底图**（自绘的干线 / 雨带 / 高风险积水段 / 补给站，全部数据驱动），
算法、剖面图、对比卡、可解释文本全部照常工作。

这条降级路径是**故意保留**的：它让 Demo 与录屏不依赖网络与配额，永远可复现。
`app/config.js` 里现在是**为「晴好出发」单独创建的浏览器端 AK**。
⚠️ 该 AK 的 Referer 白名单需要包含三个：`localhost`、`127.0.0.1`、`kint23.github.io` ——
缺哪个，那个域名下底图就不出来（会自动降级到离线示意底图，不至于白屏，但演示效果差）。

> ⚠️ **服务端 AK 与 MCP Token 永远不要写进前端**，也不要提交到仓库（`.gitignore` 已挡住 `app/config.local.js`）。

## 三、部署到 GitHub Pages

纯静态站点，无构建步骤。

```powershell
git add -A
git commit -m "晴好出发：预测驱动的物流避险与补给调度"
git push origin main
```

`.github/workflows/pages.yml` 会在推送到 `main` 时自动：
- 只发布 `index.html` + `app/`（4 个文件）+ `data/`（5 个 json）+ `README.md` + `docs/`；
- 把 `video/正片-*.mp4` 改名成 `video/demo.mp4` 一起发布（README 里引用的就是这个地址）；
- 发布 `banner/*.webp`（README 顶部的可点击动图）；
- 自动启用 Pages（`enablement: true`），无需手动去 Settings 点。

推完等 1–2 分钟，访问 `https://<user>.github.io/SunnynPoweredTrip/`。

## 四、三档备份（本机约定，已接入）

沿用主 `BACKUP.md` 配方的三档方案：① 本机 git ② 本机第二块盘的副本 ③ GitHub 仓库。
**做法与 `ohbj` 完全一致**（同名的 remote、同一条日常命令）。

| 占位符 | 值 |
|---|---|
| `$proj` | `<项目目录>` |
| `$name` | `<本机备份目录名>` |
| `$gh` | `https://github.com/Kint23/SunnynPoweredTrip.git` |

日常：`git push origin main; git push backup main`（一条命令推两档）

### 已验证状态（2026-09-30）

| 项 | 值 |
|---|---|
| 三档 SHA | 一致（`git rev-parse HEAD` / `origin/main` / 本机 `backup` 的 `main`） |
| 工作树 | 干净 |
| remote | `origin` = GitHub；`backup` = 本机第二块盘上的副本 |
| 匿名探测 | `info/refs` → **200（公开）** |
| 线上站点 | <https://kint23.github.io/SunnynPoweredTrip/> 全部 200，底图与数据均正常 |

### ⚠️ 本项目的仓库是**公开**的（与 `ohbj` 相同）

原因：**GitHub Pages 在免费账号上只能从公开仓库发布**。`ohBJ` 也是公开的。
所以这里的隐私保护**不靠仓库可见性，而靠 `.gitignore`**：

- `BACKUP.md` 必须被忽略（本项目已包含在 `.gitignore` 第 45 行，已用 `git check-ignore -v` 验证）；
- `.vscode/`（含本机解释器绝对路径）、`video/music.wav`、`video/_title.png`、`video/subs.ass` 均已忽略；
- 上传后已用匿名 API 核验：40 个文件里**没有** `BACKUP.md` / `.vscode` / 中间产物。

> 真正的硬约束是这一条：**`BACKUP.md` 绝对不能被推上去**。
> ohbj 的教训（2026-09-29）：即使后来删掉文件 + `git push --force` 重写历史，
> GitHub 仍会保留被覆盖的旧顶点（可直接用
> `api.github.com/repos/<o>/<r>/git/trees/<旧sha>` 取回），要彻底清除**只能删库重建**。
> 所以：宁可只在本机保留 BACKUP.md，也永远不要“先推上去再删”。
